# Milestone 0.1.1 — UEFI Emulator Validation

**Status:** Prepared; testing not yet performed  
**Target:** MotoDarwin AARCH64 UEFI application  
**Scope:** Emulator-only validation. This milestone does not produce a device-flashable image.

## Goal

Establish repeatable evidence that the existing MotoDarwin UEFI application can be launched by a virtual UEFI firmware in QEMU, renders its interface, and responds to the documented keyboard input.

## Current baseline

- The AARCH64 UEFI application was built locally with EDK II.
- The output reported previously is `MotoDarwinUefi.efi`.
- Its current interface is a minimal UEFI application with GOP graphics and informational menu entries.
- The entries referring to iOS 26 and stock Android are disabled/informational; they do not boot either operating system.
- A previous QEMU attempt did not establish a successful application launch. The VM starting is not proof that the application ran.
- The published `v0.1.0-dev1` `.img` is a 1 MiB non-bootable placeholder, not a firmware image, installer, or bootable disk.

## Validation plan

1. Preserve the current source and build output; do not overwrite the published placeholder.
2. Use a disposable QEMU virtual machine with AArch64 UEFI firmware and a virtual FAT filesystem containing the EFI application at the standard removable-media path: `EFI/BOOT/BOOTAA64.EFI`.
3. Boot only the virtual machine. Do not attach physical phone storage or pass through phone partitions.
4. Confirm that the virtual firmware launches the application.
5. Record whether the interface is visible, whether the expected status text appears, and whether ESC exits cleanly.
6. Save the exact QEMU command, firmware path/version, application SHA-256, console output, and screenshots or equivalent evidence.
7. Repeat the test from a clean VM setup to check reproducibility.

## Pass criteria

- QEMU starts with the selected AArch64 UEFI firmware.
- Firmware launches the expected MotoDarwin EFI application.
- The expected interface/status content is visible.
- Keyboard handling and clean exit behave as expected.
- A second run reproduces the result, with logs and hashes retained.

## Fail / blocked criteria

If the firmware cannot find or launch the application, record the exact firmware configuration, boot order, virtual disk layout, and error output. Do not mark the milestone passed merely because QEMU opens or a VM remains running.

## Out of scope

- Booting iOS, Android, XNU, or a MotoDarwin kernel.
- Testing on the physical Moto G60.
- Unlocking bootloaders, flashing partitions, or modifying device firmware.
- Claiming working Wi-Fi, graphics acceleration, touchscreen, or other physical-device drivers.
